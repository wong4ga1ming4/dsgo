# dsgo 设计方案

本文是实现依据。对外只有六条命令：`status`、`config`、`chat`、`search`、`fetch`、`ocr`。一条命令对应用户的一件事，内部可以连续调用多个 API。`POST /files` 只在 `chat` 带本地文件时内部使用，不提供 `files` 命令。

现有 `models`、`balance`、`chat` 骨架是临时入口。实现时按本文重组，不保留这三条旧命令名。

## 原则

优雅是第一要求。命令名短，参数少，默认输出能直接读。

- 无交互式对话。一次调用，一次结果，然后退出。
- 默认纯文本，写到 stdout。
- 全局 `--json` 改为给脚本用的 JSON，仍写到 stdout。
- 错误写到 stderr，成功时退出码 0，失败时退出码非 0。
- 用法错误退出码 2。API、网络、配置和文件错误退出码 1。

## 技术

- 语言：Go。
- 命令：Cobra。
- 配置：Viper。
- 配置文件：`~/.config/dsgo/config.yaml`。
- 服务地址默认 `https://api.deepseek.com`。
- 认证头：`Authorization: Bearer <API_KEY>`。

配置项：

```yaml
api_key: ""
base_url: https://api.deepseek.com
model: deepseek-flash
```

优先级从高到低：

1. 环境变量 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`。
2. 命令上的显式参数，例如 `chat --model`。
3. `--config` 指定的文件，未指定时用 `~/.config/dsgo/config.yaml`。
4. 内置默认值。

`config` 子命令只写文件，不读环境变量去覆盖文件里已有的其他字段。文件权限 `0600`，目录权限 `0700`。密钥不写进日志，不出现在错误文本里。

需要密钥的命令在发请求前检查密钥。缺失时 stderr 写「未设置 DEEPSEEK_API_KEY」，退出码 1。`config` 不访问网络，可以在没有密钥时只写入 `--model`。

## 分层

| 目录 | 职责 |
| --- | --- |
| `cmd/` | 只解析参数、调用下层、选择输出 |
| `internal/config/` | Viper 读取与写入 |
| `internal/client/` | 共用 HTTP：超时、认证、状态码、错误体 |
| `internal/api/` | 按资源封装接口，一个资源一个文件 |
| `internal/output/` | 纯文本和 JSON 两种呈现 |

`cmd/` 不拼 URL，不解析 API 的原始 JSON。`internal/api/` 不打印。`internal/output/` 不发请求。

`internal/client/` 超时：普通 JSON 请求 60 秒。上传、OCR、文档解析 300 秒。非 2xx 时取出响应里的 `error.message`，没有则使用响应正文，交给调用方写到 stderr。

## 全局参数

挂在根命令上，所有子命令都能用：

- `--config <路径>`：改用这份配置文件。
- `--json`：本次输出 JSON。

`--json` 与纯文本互斥，同一命令只走一种。JSON 是该命令的结果对象，不是把中间每个 API 的原始响应原样拼接。

## 命令

### dsgo status

确认密钥是否可用，并同时给出模型列表和余额。

调用顺序：

1. `GET /models`
2. `GET /user/balance`

两次都成功才写 stdout。任一次失败则 stderr 只写这一次的错误，退出码 1，不写另一半结果。

纯文本：

```text
密钥可用
默认模型 deepseek-flash
deepseek-flash    DeepSeek-V4.1-Flash
CNY  总额 110.00  赠送 10.00  充值 100.00
```

「默认模型」是 `chat` 不带 `--model`、`--search`、`--file` 时会用的模型：`DEEPSEEK_MODEL` 优先于配置文件里的 `model`，都没有时用 `deepseek-flash`。

账户不可用时，第一行写「密钥不可用」，退出码仍为 0，因为接口调用本身成功。没有余额条目时不写余额行。

`--json`：

```json
{
  "ok": true,
  "default_model": "deepseek-flash",
  "models": [{ "id": "deepseek-flash", "name": "DeepSeek-V4.1-Flash" }],
  "balances": [
    {
      "currency": "CNY",
      "total": "110.00",
      "granted": "10.00",
      "topped_up": "100.00"
    }
  ]
}
```

`ok` 对应响应字段 `is_available`。

### dsgo config

不调用 API。把给出的字段写入配置文件，未给出的字段保持原值。文件不存在则创建。

```text
dsgo config --apikey <密钥> --model <模型 id>
```

两个参数都可以单独使用。两个都没给时，stderr 写用法，退出码 2。

纯文本成功时只写一行：`已写入 ~/.config/dsgo/config.yaml`。实际路径用展开后的绝对路径。`--json` 写 `{"path":"..."}`。stdout 不回显密钥。

### dsgo chat

一次问答，然后退出。

```text
dsgo chat [--model 模型] [--search] [--deepthink] [--file 路径 ...] "问题"
```

问题是位置参数，必填。空问题退出码 2。三个开关都可以不带，不带时就是普通对话。

只调用 `POST /chat/completions`。请求体至少包含：

- `model`：`--model`，否则配置里的 `model`，默认 `deepseek-flash`
- `messages`：一条 `user` 消息，内容是问题
- `thinking`：默认 `{"type":"disabled"}`；带 `--deepthink` 时为 `{"type":"enabled"}`
- `stream`：`false`

`--search` 在请求里增加 `tools: [{"type":"deepseek_web_search"}]`。搜索由服务端完成，客户端不执行工具。不设置 `tool_choice`，不传 `web_search_options`。模型固定为 `deepseek-flash`，忽略 `--model` 和配置里的其他模型。单独的 `--deepthink` 只打开思考，不声明工具，模型仍按上面的规则选择。`--search` 与 `--deepthink` 一起就是深度搜索：工具仍是这一条，思考打开。

带一个或多个 `--file` 时，对每个文件先 `POST /files`，再把返回的 `id` 放进同一条用户消息。`purpose` 放在 `file` 字段之前。`--file` 可以和 `--search`、`--deepthink` 同时使用。

- PDF、Word、PowerPoint、图片：`text_recognition`
- 纯文本、表格、电子书：`user_data`

对话请求使用 Chat Completions 的文件引用，不要改走 Responses 或 Anthropic：

```json
{
  "role": "user",
  "content": [
    { "type": "file", "file_id": "file-api-..." },
    { "type": "text", "text": "问题" }
  ]
}
```

带文件时模型固定为 `deepseek-flash`，忽略 `--model` 和配置里的其他模型。上传按参数顺序进行。任一文件失败则停止，不发对话请求，stderr 写该文件路径和 API 错误。

纯文本把助手回复的 `content` 原样写出，末尾一个换行。有引用时，正文后空一行，再按出现顺序列出不重复的 URL，每行一个。不输出推理过程，不输出 `server_tool_calls`。

无引用时 `--json`：

```json
{ "model": "deepseek-flash", "content": "回复正文" }
```

有引用时增加 `citations`，值为 URL 字符串数组。

带 `--search`、`--deepthink` 或 `--file` 时，这次对话请求的超时为 300 秒。不进入多轮等待。

### dsgo search

回答「搜一下并看到正文」，不是链接列表。

```text
dsgo search "查询"
```

查询必填，去掉首尾空白后长度 1 到 128。否则退出码 2。

调用顺序：

1. `POST /v1/tools/search`，`query` 为用户查询，`count` 为 3，`need_content` 为 `false`。
2. 按返回顺序，对每条结果的 `url` 调用 `POST /v1/tools/fetch`。

某一页抓取失败时跳过该页，继续下一页。三页都失败，或搜索结果为空，stderr 写明原因，退出码 1。

纯文本按命中顺序输出，页与页之间空一行。每页先写标题，再写 `fetch` 返回的 Markdown 正文。不写 URL 列表。

`--json`：

```json
{
  "query": "查询",
  "pages": [{ "title": "标题", "content": "正文" }]
}
```

`pages` 只包含抓取成功的页，顺序与搜索结果一致。

### dsgo fetch

只抓一页，返回正文。

```text
dsgo fetch <url>
```

`POST /v1/tools/fetch`，请求体 `{"url":"<url>"}`。URL 必填，否则退出码 2。

纯文本先写 `title`，换行后写 `content`。`--json` 就是 `{"title":"...","content":"..."}`。

### dsgo ocr

识别文档或图片里的文字。

```text
dsgo ocr <file>
```

`POST /v1/tools/ocr`，`multipart/form-data` 两个必填字段：`purpose=text_recognition`，`file` 为本地文件。格式按文件实际内容判断，接受：

- 文档：PDF、Word（DOC、DOCX）、PowerPoint（PPT、PPTX）
- 图片：PNG、JPEG、WebP、GIF、BMP、TIFF

文件不存在时退出码 1，不发请求。不在 CLI 里转格式。服务端限制是 100 MiB 和 1,000 页，超出由接口返回错误，原样写到 stderr。

纯文本按 `pages` 的 `index` 顺序拼接 `text`，页之间空一行。`--json`：

```json
{
  "pages": [{ "index": 0, "text": "识别出的文字" }]
}
```

## 不对外的能力

- 不提供 `files`、`models`、`balance`、`asr` 命令。模型列表和余额只通过 `status` 出现。语音识别不对外，接口最长 120 秒。
- 不实现 Responses API 和 Anthropic Messages。对话里的联网只通过 `chat --search` 与 `--deepthink` 开启，不另设命令。
- 不提供交互式 REPL，不为 `chat` 保存历史。
- 上传得到的 `file_id` 不打印，除非将来单独把 `--json` 的字段设计进去。当前 `chat` 的 JSON 不包含 `file_id`。

## 实现顺序

1. 换成 Cobra 和 Viper，完成配置优先级和全局 `--json`、`--config`。
2. 完成 `config` 和 `status`。`status` 同时验证密钥、模型和余额。
3. 完成不带文件的 `chat`，再完成内部上传和带文件的 `chat`。
4. 完成 `fetch`，再完成会调用它的 `search`。
5. 完成 `ocr`。

每完成一条命令，用纯文本和 `--json` 各验一次。没有密钥时只验证参数错误和配置写入。
